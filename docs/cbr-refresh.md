# Обновление курсов несколькими инстансами

Каждый API имеет локальный кеш и Refresher. Право запроса к ЦБ выдаёт общая PostgreSQL:
`rate_refresh_leases` содержит ключ работы, случайного владельца, возрастающую версию,
срок lease, срок следующей попытки и время последнего успеха. Все инстансы должны
использовать одну БД. Запрос latest общий, исторические запросы координируются по дате запроса.

Claim атомарен. Только победитель обращается к ЦБ. HTTP выполняется без открытой SQL-транзакции.
Для latest используется существующий request timeout; lease в сборке приложения равен
RequestTimeout + DB.StatementTimeout + 5 секунд. Успешная фиксация проверяет владельца,
версию и действующий lease под блокировкой строки, сохраняет пакет и переносит общий
next_attempt_at на RefreshInterval. Если lease истёк во время сохранения, транзакция откатывается.

При ошибке, отмене и панике выполняется попытка освобождения с общим RetryInterval
через отдельный cleanup-контекст (не более 5 секунд). Если процесс погиб и cleanup
не выполнен, lease истечёт сам; новый владелец получит другой UUID и версию.
Старый владелец не сможет сохранить ответ или сбросить расписание нового.

Follower не обращается к ЦБ и читает курсы из БД. Проверка общей координации и обновление
локальных кешей выполняются не реже одного раза в 30 секунд при нормальной работе;
после локальной ошибки используется RetryInterval. Это оставляет небольшие запросы к БД,
но не создаёт 60 HTTP-запросов и 60 записей курсов. Значения кешируются после чтения
реально сохранённых, округлённых значений. Даже при неизменной дате курса (выходные)
повторные HTTP-запросы ограничены next_attempt_at, а не проверкой даты курса.

При сетевом разделении или длительной остановке процесса возможен запоздавший HTTP-запрос,
который пересечётся с запросом нового владельца. Exactly-once для внешнего HTTP не обещается:
защита гарантирует единственного актуального писателя в PostgreSQL. Если сама БД недоступна,
обновление закрывается ошибкой: обхода координации прямым запросом к ЦБ нет, старый кеш сохраняется.

Перед запуском применить миграцию 000003. Новых env-переменных нет: используются
RATES_REFRESH_INTERVAL, RATES_RETRY_INTERVAL и RATES_REQUEST_TIMEOUT.
Локальную рабочую БД эта разработка автоматически не мигрирует.
